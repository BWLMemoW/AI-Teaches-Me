## 1. 技术栈

### 1.1 技术路线

一句话：**Python 桌面壳（PySide6）+ 内嵌 Chromium 渲染页（QtWebEngine）+ OpenAI 兼容模型客户端 + 本地文件系统与 SQLite 双轨存储**。

- 业务逻辑全部在 Python 侧，UI 只做展示与交互；
- 教学内容用「文本 + 结构化块」双份落盘（Markdown 供人读，NDJSON 供机器精确复现）；
- 所有渲染依赖（Markdown / 公式 / 代码高亮）随包分发，**断网可用**，不引用任何 CDN；
- 模型能力（讲课 / 读图 / 联网）通过「供应商档案 + 任务路由」解耦，换模型不动课程数据。

### 1.2 技术栈总表

| 层次 | 选型 | 版本基线 | 选型理由 |
| --- | --- | --- | --- |
| 语言 | Python | 3.11+（当前 3.11.4） | 环境就绪；AI 与文档解析生态最全 |
| 桌面框架 | PySide6（Qt 6） | ≥ 6.6 | 原生桌面体验；LGPL 许可友好；自带 QtWebEngine / QtSvg |
| 内嵌渲染 | QtWebEngine（Chromium） | 随 PySide6 | 承载 Markdown、KaTeX 公式、代码高亮、SVG 与 HTML 动画，可完全离线加载本地资源 |
| 模型接入 | `openai` SDK（OpenAI 兼容协议） | ≥ 2.0（当前 2.41.0） | 一套协议覆盖 OpenAI / DeepSeek / 通义 / Moonshot / Ollama / vLLM / One-API 网关 |
| HTTP 细则 | `httpx` | ≥ 0.27 | 控制超时、代理、流式与重试细节（搜索后端直连也复用它） |
| 默认模型档案 | DeepSeek（`deepseek-flash`，`https://api.deepseek.com/v1`） | — | 响应快、成本低、中文自然；**自带多模态读图**，视觉任务无需外接模型 |
| 模型路由 | 自研 `core/routing.py` | — | 按任务（讲课 / 视觉自检 / 联网）分发到不同供应商档案 |
| 结构化输出 | `pydantic` | ≥ 2.7 | 总监 Agent 的大纲输出校验、配置与领域模型定义 |
| 文档解析 | `pypdf` / `python-pptx` / `python-docx` / `Pillow` | 5.1 / ≥1.0 / ≥1.1 / ≥10.0 | 覆盖 PDF / PPTX / DOCX / 图片四类素材 |
| 检索 | SQLite **FTS5**（`tokenize='trigram'`，需 SQLite ≥ 3.34） | 随标准库 | 零额外服务依赖；**中文检索必须用 trigram**（`unicode61` 不做 CJK 分词，会导致中文检索失效）；资料片段按页定位检索 |
| Markdown 处理 | `Markdown`（服务端）+ `markdown-it`（前端 vendor） | ≥ 3.7 | 服务端产出人读版 `script.md`，前端渲染内容块 |
| 公式 / 高亮 | `KaTeX` + `highlight.js`（本地 vendor）、`pygments` | — | 离线渲染公式与代码，无网络请求 |
| SVG 处理 | QtSvg（`svg_renderer.py`）+ 自研 `svg_sanitizer.py` | 随 PySide6 | 生成图先渲染成 PNG 供自检与占位，再做白名单清洗 |
| 联网搜索 | 可插拔四类后端（默认**百度千帆 AI 搜索**） | — | 搜索能力与主模型解耦；默认预设一次调用即返回引用列表 |
| 数据存储 | 文件系统（课程）+ SQLite（索引 / 会话 / 用量） | — | 课程可读、可备份、可迁移；索引层保证大课程库性能 |
| 配置 | `data/config.json` + 系统凭据库 | — | 明文配置与敏感凭据分离 |
| 密钥存储 | `keyring`（Windows 走 DPAPI） | ≥ 25.0 | 密钥不落明文，导出与日志一律脱敏 |
| 目录规范 | `platformdirs` | ≥ 4.0 | 跨平台目录约定 |
| 打包 | PyInstaller（首选）/ Nuitka（备选） | — | 单目录分发，Windows 双击即用 |
| 测试 | `pytest` + `pytest-qt` + 录制式 LLM 桩 | — | 无网络可回归；覆盖领域、契约、渲染与 UI |

### 1.4 备选方案与结论

| 方案 | 优势 | 劣势 | 结论 |
| --- | --- | --- | --- |
| PySide6 + QtWebEngine | 原生性能、Web 渲染能力、Python AI 生态直连 | 打包体积较大（约 150–250MB） | ✅ 采用 |
| Electron + Node | 前端生态丰富、UI 灵活 | 内存占用高、Python AI 工具链需跨进程桥接 | ❌ 不采用 |
| Tauri + Rust | 体积小、性能好 | 需 Rust、与 Python AI 生态割裂 | ❌ 不采用 |
| WPF / WinUI (.NET) | Windows 原生体验佳 | 跨平台差、AI 生态弱 | ❌ 不采用 |
| 纯 Web（浏览器打开本地服务） | 开发快 | 明确不符合「PC 客户端，不是浏览器」的需求 | ❌ 违反需求 |

### 1.5 技术约束（红线）

1. 🔒 **UI 层不得直接调用 LLM SDK**：`app/ui/` 中出现 `from openai import ...` 视为架构违规，由 lint 规则禁止。
2. 🔒 **应用服务层不导入 Qt**：`app/services/` 必须可无界面单测。
3. 🔒 **基础设施层不含业务规则**：`app/infra/` 只做技术细节（IO、协议、清洗）。
4. 🔒 **渲染资源全部本地**：`app/web/vendor/` 提供 Markdown / KaTeX / highlight.js，禁止 CDN 与外链。
5. 🔒 **绝不在主线程做网络请求或文档解析**：全部经线程池或异步桥接。
6. 🔒 **课程数据与程序目录分离**：升级程序不影响 `Courses/` 与 `data/`。
7. 🔒 **密钥不落明文**：不写入 `course.json`、日志、导出文件与崩溃报告。

### 1.6 运行环境与非功能指标基线

| 类别 | 指标 |
| --- | --- |
| 冷启动 | 应用冷启动到可交互 ≤ 3s（不含模型请求） |
| 课程库规模 | 500 门课程滚动流畅，列表首屏 ≤ 200ms；1000 门下搜索 / 标签筛选 ≤ 200ms |
| 流式渲染 | 首字 ≤ 5s；每秒 ≥ 20 token 时 UI 不掉帧（回调节流 30–60ms） |
| 渲染内核 | 单块渲染 ≤ 16ms；100 块讲义首屏 ≤ 300ms；公式与高亮零网络请求 |
| 长讲义滚动 | 1000 块级内容不掉帧（可视区虚拟渲染 + 图片懒加载） |
| SVG 自检 | 单张图示「渲染 + 自检 + 必要重画」总耗时 ≤ 40s（默认 3 轮内） |
| 工具调用 | 单轮额外延迟 ≤ 15s（搜索）/ 30s（读图）；超时中断该轮，模型基于已有信息继续 |
| 崩溃恢复 | 讲义与追问按块增量落盘，崩溃最多丢最后 1 块 |
| 离线 | 无网络时可浏览与阅读所有已生成内容 |
| 平台 | Windows 10/11 优先；macOS / Linux 保持可运行（不做专项优化） |

## 2. 系统架构与系统关系

### 2.1 总体分层

```text
┌──────────────────────────────────────────────────────────────────────┐
│  UI 层 (PySide6 + QWebEngineView)                                    │
│  主窗口 / 课程库 / 创建向导 / 学习台 / 小灶 / 笔记中心 / 设置 / 主题 │
│  - 只依赖应用服务暴露的接口，不直接调用 LLM SDK                       │
└───────────────▲──────────────────────────────┬───────────────────────┘
                │ 事件 / 视图模型 (Signal-Slot) │ 命令 (Command)
┌───────────────┴──────────────────────────────▼───────────────────────┐
│  应用服务层 (Application Services)                                    │
│  CourseService · OutlineService · LessonService · MaterialService    │
│  ProgressService · SettingsService · ExportService · BackupService    │
│  - 用例编排、事务边界、进度落盘、取消 / 重试                          │
└───────────────▲──────────────────────────────┬───────────────────────┘
                │                              │
┌───────────────┴──────────────┐  ┌────────────▼───────────────────────┐
│  Agent 编排层                │  │  领域层 (Domain)                    │
│  Director · Teacher          │  │  Course · Chapter · Lesson · KP      │
│  Illustrator · Animator      │  │  ContentBlock · Progress · Material  │
│  Tutor · Q&A · NoteKeeper    │  │  纯数据结构 + 校验规则（Pydantic）   │
│  ToolRegistry · ContextStore │  └────────────▲───────────────────────┘
└───────────────▲──────────────┘               │
                │                              │
┌───────────────┴──────────────────────────────┴───────────────────────┐
│  基础设施层 (Infrastructure)                                          │
│  LLMClient(openai) · StreamParser · MaterialParser · Retriever       │
│  FileRepository · SqliteIndex · SecretStore · SandboxRenderer · Log  │
└──────────────────────────────────────────────────────────────────────┘
```

**依赖方向**：`UI → 应用服务 → Agent / 领域 → 基础设施`。
Agent 层与基础设施层**不依赖 UI**，保证可单测、可替换；领域层不依赖任何外部服务。

### 2.2 系统关系一图速览

| 关系 | 说明 |
| --- | --- |
| UI ↔ 应用服务 | 唯一的用户操作入口；命令下行，事件 / 视图模型上行 |
| 应用服务 ↔ Agent | 服务负责编排与事务，Agent 负责生成；服务不解析模型文本 |
| Agent ↔ 领域模型 | Agent 的产出必须校验为领域模型 / 内容块，才允许落盘 |
| Agent ↔ 基础设施 | 通过 `LLMClient`、`ToolExecutor`、`FileRepository` 访问外部世界 |
| 基础设施 ↔ 外部系统 | 只与用户配置的模型端点、搜索后端通信，无遥测 |
| 文件系统 ↔ SQLite | 文件系统是**唯一事实来源**，SQLite 是可重建的索引 / 统计缓存 |

                                          └───┬───────────┬───┘
                                              │           │
                                    ┌─────────▼──┐  ┌─────▼─────────┐
                                    │ 文件系统    │  │ 外部服务      │
                                    │ Courses/    │  │ 模型端点      │
                                    │ data/       │  │ 搜索后端      │

```

关键约束：**服务层是事务边界**。任何「先写文件再写索引」的复合动作必须在服务层完成，Agent 与基础设施各自都不知道全局事务。

### 2.5 Agent 关系

| Agent | 触发时机 | 输入 | 输出 | 流式 | 可调工具 |
| --- | --- | --- | --- | --- | --- |
| 课程总监 Director | 创建课程 / 细化大纲 | 课程名、用户大纲、资料摘要、澄清答案 | 澄清问题、教学大纲 | 是 | 联网、读资料 |
| 教师 Teacher | 进入未生成的小节 / 点「重讲」 | 小节知识点、资料片段、人设、深度档位、完整大纲 | 富内容块序列（讲义） | 是 | 全部教学工具 |
| 图示 Illustrator | 教师请求画示意图 / 用户点「重画」 | 概念描述、视觉风格、已有 SVG（重画时） | 单文件 SVG 矢量图 | 否 | 渲染自检、读图 |
| 动画师 Animator | 教师请求演示抽象概念 | 概念描述、参数、视觉风格 | 单文件 HTML 动画 | 否 | — |
| 助教 Tutor | 小节内追问 / 请求练习 | 追问文本、小节上下文、选中片段 | 富内容块序列（答疑） | 是 | 读资料、联网 |
| 答疑顾问 Q&A | 小灶（课内答疑）提问 | 引用卡片集合（限本课程）、大纲摘要、历史答疑 | 富内容块序列（答疑） | 是 | 读资料、联网 |
| 笔记整理 NoteKeeper | 小节完成 / 用户点「生成笔记」 | 讲义、追问、用户笔记、掌握度 | 结构化 Markdown 笔记 | 否 | — |
| 审核 Reviewer（可选） | 讲解完成后 | 讲义 + 资料片段 | 事实性问题清单（防幻觉） | 否 | — |

                     ┌─────────────────────────┐
                     │ Director（课程级，1 次） │
                     └────────────┬────────────┘
                                  │ 产出 outline.json
                     ┌────────────▼────────────┐
                     │ Teacher（小节级，N 次） │◀── Persona 装配（表达层）
                     └──┬────────┬────────┬────┘
            调用子能力   │        │        │  追问/答疑共享同一骨架
              ┌─────────▼──┐ ┌───▼──────┐ └──────────▶ Tutor（小节内追问）
              │ Illustrator│ │ Animator │              Q&A（小灶，仅本课程）
              └─────┬──────┘ └──────────┘                   │
                    │ 渲染自检（Render-and-Review）          │
                    ▼                                       ▼
              讲义内容块 ─────────────────────────▶ NoteKeeper（笔记沉淀）
                    │
                    ▼
        渲染内核（教学区 / 追问抽屉 / 小灶 三处共用）
```

> Teacher / Tutor / Q&A / NoteKeeper **共享同一套「教学骨架 + 人设」基底**，只是任务模板与工具权限不同：**骨架保证讲得对，人设决定讲得有趣**。

### 2.6 模型路由关系

| 路由键 | 用途 | 默认指向 | 能力要求 |
| --- | --- | --- | --- |
| `routing.teach` | 教师讲解、追问、答疑、笔记 | `deepseek-default` | 文本 + 长上下文 |
| `routing.outline` | 总监生成大纲 | `deepseek-default` | 结构化 JSON 输出 |
| `routing.illustrate` | SVG / 动画生成 | `deepseek-default` | 代码生成 |
| `routing.vision_review` | SVG 渲染自检（读图评审） | `deepseek-default` | `capabilities.vision = true` |
| `routing.web_search` | **仅当** `backend = "openai_hosted"` 时使用的档案 | `null` | `capabilities.hosted_web_search = true` |

规则：

1. 档案在 `data/config.json` 的 `llm_profiles` 中定义，`active_profile` 是默认档；路由未配置时回落到 `active_profile`。
2. 视觉任务先看档案的 `vision_model`，为空则**沿用对话模型**（DeepSeek 已内置多模态读图，无需外接视觉模型）。
3. 档案 `capabilities.vision = false` 时，视觉自检自动退回启发式检查，并在界面提示更换模型。
4. 默认后端千帆 AI 搜索是**独立 HTTP 端点**，不占用供应商档案，因此 `routing.web_search` 保持 `null`。

### 2.8 进程与线程

| 执行体 | 承担的工作 |
| --- | --- |
| 主线程（Qt GUI） | 所有 UI 绘制与控件操作 |
| 工作线程（QThreadPool / asyncio） | LLM 流式请求（httpx / openai async）、动画 HTML 组装与校验、检索与索引（写操作队列串行化） |
| 独立进程池 | 文档解析等 CPU 密集任务，避免 GIL 阻塞界面 |

约定：

1. 工作线程 → 主线程只用**跨线程 Signal**，不直接触碰控件。
2. 每个长任务持有 `CancellationToken`，用户可随时中断。
3. 取消语义：取消请求 → 关闭连接 → **保留已完成块** → 小节状态标记为「未完成」。
4. 流式回调节流 30–60ms 合并刷新，避免高频重绘（对应 `generation.stream_throttle_ms`，默认 40）。

## 3. 数据存储结构

### 3.1 存储介质与分工

| 介质 | 存什么 | 是否唯一事实来源 | 删除后的后果 |
| --- | --- | --- | --- |
| 文件系统（`Courses/`、`personas/`） | 课程结构、讲义、追问、笔记、视觉产物、用户人设 | ✅ 是 | 数据丢失，无法自动恢复 |
| SQLite（`data/library.db`） | 课程索引、资料索引与 FTS5 检索、用量日志、标签、智能视图、人设登记 | ❌ 否，**可重建** | 自动扫描 `Courses/` 重建（标签与智能视图有落盘副本） |
| 系统凭据库 + `data/secrets.bin` | API Key（DPAPI / keyring 加密） | ✅ 是 | 需用户重新填写密钥 |
| 缓存（`data/cache/`） | 缩略图、SVG、动画、搜索结果 | ❌ 否 | 重新生成即可，仅影响速度与成本 |
| 日志（`data/logs/`） | 结构化脱敏日志，按天切割，默认保留 30 天 | ❌ 否 | 丢失排查依据，不影响功能 |

> 设计原则：**课程内容永远是普通文件**（JSON + Markdown + SVG + HTML），不锁进数据库；数据库只承担「查得快」这件事，因此可以随时删库重建。

### 3.2 工作区根目录

```text
<用户数据根目录>/                       # 首次启动时选择，默认应用同级目录；可改为网盘目录
├─ Courses/                            # 课程库（用户核心资产，可整体备份 / 迁移）
│   └─ <课程名>/                        # 见 3.3
├─ personas/                           # 用户自建 / 导入的教学人设（.md）
├─ data/
│   ├─ config.json                     # 供应商档案、主题、偏好（不含明文密钥）
│   ├─ secrets.bin                     # 加密后的 API Key（DPAPI / keyring 备份）
│   ├─ library.db                      # SQLite：课程索引、资料索引、FTS5、用量、标签
│   ├─ cache/                          # 缩略图、SVG、动画、搜索结果缓存
│   └─ logs/                           # 结构化日志（脱敏，按天切割，默认保留 30 天）
└─ models/                             # 预留：本地模型或 embedding 缓存
```

### 3.3 单门课程目录

```text
Courses/线性代数速通/
├─ course.json                         # 课程元信息（含 schema_version）
├─ outline.json                        # 教学大纲（章 / 小节 / 知识点，结构化）
├─ outline.md                          # 大纲人读版（由 outline.json 生成）
├─ progress.json                       # 进度、时长、掌握度、复习队列
├─ assets/
│   ├─ cover.png                       # 封面
│   └─ bg.png                          # 该课程可选的自定义背景
├─ materials/                          # 用户上传资料与解析产物
│   ├─ raw/教材第3版.pdf
│   ├─ parsed/教材第3版.md              # 带分页标记的解析结果
│   └─ materials.json                  # 资料清单与解析状态
├─ chapters/
│   └─ C1-矩阵与线性方程组/
│       ├─ chapter.json                # 章元信息（标题、摘要、小节顺序）
│       └─ lessons/
│           └─ L1-2-矩阵乘法/
│               ├─ lesson.json          # 小节元信息、状态、版本
│               ├─ script.md            # 讲义正文（当前版本，人读友好）
│               ├─ script.blocks.jsonl  # 讲义结构化块（精确复现渲染）
│               ├─ history/             # 历史版本（v1.md / v1.blocks.jsonl）
│               ├─ chat.jsonl           # 追问会话记录（追加写）
│               ├─ widgets/             # 本小节生成的视觉产物
│               │   ├─ diagram-1.svg        # SVG 图示（当前版本）
│               │   ├─ diagram-1.v2.svg     # 重画历史版本
│               │   ├─ diagram-1.png        # 渲染自检图 / 首屏占位图
│               │   └─ animation-1.html     # HTML 微动画
│               └─ notebook.md          # 用户手写笔记
├─ notes/                              # AI 整理的课程笔记（可导出）
│   ├─ C1/
│   │   └─ L1-2.md                      # 小节笔记（NoteKeeper 生成）
│   └─ 小灶汇总.md                       # 小灶沉淀的结论
├─ qa/
│   └─ sessions.jsonl                   # 小灶会话（引用卡片 + 问答，仅限本课程）
└─ exports/                            # 导出的 Markdown / PDF / 备份 zip
```

设计理由：

1. **人可读**：`script.md` / `outline.md` / `notebook.md` 为 Markdown，可直接用任意编辑器打开、同步网盘或纳入 Git。
2. **机器可读**：元信息一律 JSON；`script.blocks.jsonl` 保证动画、测验答案、SVG 等富内容可精确复现。
3. **可恢复**：`history/` 与追加写日志保证内容不被覆盖丢弃。
4. **可手工介入**：手工往 `Courses/` 放一个符合结构的课程文件夹，刷新后即可被识别。
5. **风格可回溯**：讲义与笔记记录生成时使用的人设 id / 版本，切换人设后可对比同名内容的不同风格。
6. **答疑独立**：小灶写在课程内 `qa/`，不污染小节教学记录，便于整门课程回看与导出。

### 3.7 SQLite 表结构（`data/library.db`）

```sql
CREATE TABLE courses (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, path TEXT NOT NULL UNIQUE,
  updated_at TEXT, total_lessons INTEGER, completed_lessons INTEGER,
  cover TEXT, description TEXT
);

CREATE TABLE materials (
  id TEXT PRIMARY KEY, course_id TEXT, filename TEXT, kind TEXT,
  pages INTEGER, parsed_at TEXT, status TEXT, checksum TEXT
);

CREATE VIRTUAL TABLE material_chunks USING fts5(
  material_id UNINDEXED, page UNINDEXED, heading, text,
  tokenize='trigram'          -- 中文检索必须用 trigram；unicode61 不做 CJK 分词，会导致中文检索失效
);

CREATE TABLE usage_log (
  ts TEXT, course_id TEXT, lesson_id TEXT, agent TEXT,
  model TEXT, prompt_tokens INTEGER, completion_tokens INTEGER
);

CREATE TABLE tags (
  id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL UNIQUE,
  color TEXT, created_at TEXT
);

CREATE TABLE course_tags (
  course_id TEXT NOT NULL, tag_id INTEGER NOT NULL,
  PRIMARY KEY (course_id, tag_id)
);
CREATE INDEX idx_course_tags_tag ON course_tags(tag_id);

CREATE TABLE personas (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, builtin INTEGER DEFAULT 0,
  path TEXT, version INTEGER DEFAULT 1, updated_at TEXT
);

CREATE TABLE qa_sessions (
  id TEXT PRIMARY KEY, course_id TEXT, title TEXT,
  created_at TEXT, updated_at TEXT, message_count INTEGER DEFAULT 0
);

CREATE TABLE saved_views (
  id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL,
  query TEXT NOT NULL, created_at TEXT
);
```

```text
courses ──1:N── materials ──1:N── material_chunks (FTS5)
   │                 (course_id)        (material_id)
   ├──N:M── tags        （经 course_tags）
   ├──1:N── qa_sessions
   └──1:N── usage_log（按 course_id / lesson_id 记账）
personas、saved_views 独立表；saved_views.query 存筛选条件 JSON
```

> **分词器定稿（对应 C-03）**：中文检索一律使用 `tokenize='trigram'`（需 SQLite ≥ 3.34），**`unicode61` 不作为本项目的检索分词器** —— 它按 Unicode 类别切词、不做 CJK 分词，中文整句几乎无法命中。已知限制：trigram 对长度 < 3 的查询串（如单字「熵」）无法走索引，此时回退为 `LIKE` 扫描（资料库规模有限，性能可接受）。

可重建性规则：

1. `library.db` 视为**缓存**：删除后应用扫描 `Courses/` 自动重建（课程、资料、用量统计均可重建）。
2. **唯一例外**：标签与智能视图属于用户输入，除写库外还同步落盘到 `Courses/.library/tags.json` 与 `Courses/.library/saved_views.json`，保证删库不丢。
3. `usage_log` 只增不删，用于成本可视化与每日预算判定。
4. 写操作用队列串行化（SQLite 单写多读），避免并发写锁冲突。

### 3.10 缓存

| 缓存 | 路径 | 失效策略 |
| --- | --- | --- |

### 3.11 一致性、原子写与版本迁移

**原子写**

```python
def atomic_write_text(path: Path, text: str) -> None:
    tmp = path.with_suffix(path.suffix + ".tmp")
    tmp.write_text(text, encoding="utf-8")
    os.replace(tmp, path)          # 同分区原子替换
```

- 讲义每完成一个块就重写 `script.md` 并追加 `script.blocks.jsonl`；
- `chat.jsonl` / `qa/sessions.jsonl` 使用追加写，逐行 flush；
- 启动时若发现 `.tmp` 残留，说明上次写入中崩溃：丢弃临时文件，保留原文件。

**`schema_version` 迁移**

| 情形 | 处理 |
| --- | --- |
| 文件版本 == 应用支持版本 | 正常读写 |
| 文件版本 < 应用支持版本 | 按 `app/core/migrations/` 逐级迁移；迁移前把原文件备份到 `history/` 或同名 `.bak` |
| 文件版本 > 应用支持版本（用户降级应用） | 进入**只读模式**：可浏览与导出，禁止写入，并提示升级应用 |
| 迁移失败 | 保留原文件不动，课程标记为「需要修复」，在课程库给出提示与备份入口 |

**路径安全**（写入前必须通过）

```python
WINDOWS_RESERVED = {"CON","PRN","AUX","NUL","COM1",...,"LPT9"}

def safe_component(name: str) -> str:
    name = re.sub(r'[<>:"/\\|?*\x00-\x1f]', "", name).strip(" .")
    if not name or name.upper().split(".")[0] in WINDOWS_RESERVED:
        raise InvalidName(name)
    return name[:80]

def safe_join(root: Path, *parts: str) -> Path:
    target = (root.joinpath(*parts)).resolve()
    if not str(target).startswith(str(root.resolve()) + os.sep):
        raise PathEscape(target)      # 拒绝 ../ 逃逸
    return target
```

**删除与备份**

1. 删除课程走**回收站**（不直接 `rm`），并二次确认。
2. 启动时做课程目录结构校验，缺失关键文件标记为「需要修复」。
3. 支持整库 / 单课程备份为 zip，可在新机器恢复（备份包不含密钥）。
4. 种子课程升级需**逐文件比对**，仅当文件未被用户修改时才覆盖，升级前自动备份。

## 4. 系统交互方式

### 4.1 交互总览

| 类别 | 参与方 | 载体 / 协议 | 典型场景 |
| --- | --- | --- | --- |
| ① 层间交互 | UI ↔ 应用服务 ↔ Agent | Python 调用 + Qt Signal-Slot（同进程） | 点开小节、标记完成、切换主题 |
| ② 模型交互 | Agent ↔ LLM 端点 | HTTPS + OpenAI 兼容 `chat.completions`（流式）+ **NDJSON 内容块协议** | 生成大纲、讲解、追问、笔记 |
| ③ 工具交互 | Agent ↔ 本地工具 ↔ 外部服务 | Function Calling（JSON Schema 注册）+ `ToolExecutor` | 联网搜索、读大纲、查资料、读图、画图 |
| ④ 渲染交互 | 应用 ↔ 内嵌页面 | `QWebEngineView` 加载本地 `lesson.html` + `QWebChannel` 桥 + CSP | 讲义渲染、动画沙箱、主题换色 |

 ▼
UI 页面 ──①命令──▶ 应用服务 ──调用──▶ Agent ──②流式请求──▶ LLM 端点
   ▲                  │                  │  ▲                │
   │ ①事件/视图模型    │ 事务/落盘        │  │ ③tool 结果回喂  │ ②NDJSON 块

### 4.2 UI ↔ 应用服务（命令 / 事件）

采用「**命令下行、事件上行**」的单一入口模式，UI 不直接触碰文件、数据库与模型。

| UI 动作 | 服务方法（示例） | 回传事件 |
| --- | --- | --- |
| 新建课程（向导确认） | `outline_service.commit(course)` | `course-created`（课程库插入卡片） |
| 点开小节 | `lesson_service.get_or_create(lesson_id)` | `script-started` / `script-block` / `script-done`（流式） |
| 追问 | `lesson_service.ask(text, selection)` | `chat-delta` / `chat-done` |
| 标记完成 | `progress_service.mark_complete(lesson_id)` | `progress-updated`（章节树与进度环刷新） |
| 切换主题 | `settings_service.set_theme(key)` | `theme-changed`（Qt QSS + 内嵌页面 CSS 变量同步） |
| 停止生成 | `cancel(token)` | `script-cancelled`（保留已完成块） |

规则：

1. UI **不组装提示词、不解析模型文本、不写文件**；
2. 长任务必须暴露三件套：**阶段进度、可取消、可重试**；
3. 错误提示必须包含「重试 / 换模型 / 查看详情」中至少一项，并展示「状态码 + 人话解释 + 排查建议」。

### 4.3 应用服务 ↔ Agent

服务负责「组织材料、界定事务、决定落盘」，Agent 只负责「读上下文 → 生成 → 产出块」。

| 服务 | Agent | 服务提供 | Agent 返回 |
| --- | --- | --- | --- |
| `outline_service` | Director | 课程名、用户大纲、资料摘要、澄清答案 | 澄清问题列表 / `CourseOutline` JSON |
| `lesson_service` | Teacher | 小节知识点、大纲、人设、深度、资料片段 | 内容块序列（NDJSON） |
| `lesson_service` | Illustrator / Animator | 概念描述、视觉规范、已有 SVG | SVG 源码 / 动画 HTML |
| `lesson_service` | Tutor | 追问文本、小节上下文、选中片段 | 答疑内容块序列 |
| `qa_service` | Q&A | 本课程引用卡片集合、大纲摘要、历史答疑 | 答疑内容块序列 |
| `notes_service` | NoteKeeper | 讲义、追问、用户笔记、掌握度 | 结构化 Markdown 笔记 |

落盘节奏由服务决定：**每完成一个内容块即增量落盘**（原子写），因此 Agent 中途失败或用户取消时，已生成内容不丢。

### 4.4 Agent ↔ LLM

#### 4.4.1 统一出口

所有模型调用只经过一个出口 `app/llm/client.py`，它负责档案切换、重试、流式、用量统计。

```python
async def stream_chat(self, messages, *, profile=None, model=None,
                      tools=None, json_schema=None, cancel=None):
    for attempt in range(self.max_retries):
        try:
            async with self._open(profile, model) as client:
                stream = await client.chat.completions.create(
                    model=model or self.chat_model,
                    messages=messages,
                    stream=True,
                    response_format=("json_schema", json_schema) if json_schema else None,
                    tools=tools or None,
                )
                async for chunk in stream:
                    if cancel and cancel.cancelled:
                        return
                    yield chunk.choices[0].delta.content or ""
                self.usage.record(...)
                return
        except RetryableError:                 # 429 / 5xx / 网络超时
            await asyncio.sleep(backoff(attempt))
        except AuthError:                      # 401 / 403
            raise                              # 配置问题，重试无用
```

| 错误类别 | 处理 |
| --- | --- |
| 401 / 403 | 立即上报，**不重试**；UI 引导检查 API Key 与 Base URL |
| 429 / 5xx / 网络超时 | 指数退避重试，默认 3 次 |
| 用户取消 | 立刻关闭连接并返回，保留已完成块 |
| 模型拒答 / 空响应 | 切换备用档案重试一次；仍失败则展示可重试错误卡 |

#### 4.4.2 提示词装配顺序

提示词以文件形式管理（不硬编码在 Python 里），按固定顺序装配，低优先级在前：

```text
shared/safety.md → shared/untrusted.md → shared/style.md → teacher/skeleton.md
  → <工作区>/personas/<当前人设>.md   ← 只影响表达层
  → teacher/depth_<档位>.md → teacher/protocol.md → shared/coverage.md
```

**分层夹逼**：把「骨架 + 协议 + 覆盖率校验」放在人设前后两端，降低人设越权概率；人设正文命中越权规则（如「不要输出」「省略」「忽略上面的」）时，装配阶段剔除该行并提示「已忽略 N 条与教学规则冲突的指令」。

#### 4.4.3 教师 Agent 的上下文

```text
system : 教学骨架（固定）+ 当前人设全文（可换）+ 输出协议 + 安全约束
context:
    ├─ 课程名 / 课程学习目标 / 目标读者
    ├─ 当前人设（语气、称呼、口吻要求）
    ├─ 完整课程大纲（可经工具读取；含本小节位置、前后小节、本章目标）
    ├─ 本小节知识点清单（自动注入，生成后逐条校验覆盖率）
    ├─ 当前章摘要 + 前一小节小结（≤300 字）
    ├─ 当前小节：标题 / 学习目标 / 知识点清单 / 建议时长
    ├─ 资料检索片段（top-k，带 file + page，总量受预算控制）
    ├─ 联网搜索结果（仅在开启且触发时；带标题 + 域名 + 访问时间）
    ├─ 用户画像（水平；偏好：爱例子 / 爱推公式 / 爱故事）
    └─ 用户已提过的疑问关键词（避免重复啰嗦）
user   : 「请按五段式讲解本小节，深度 = 标准，用 NDJSON 输出」
```

深度档位只改篇幅与展开程度（极简 3–5 分钟 / 标准 8–15 分钟 / 深入 20 分钟以上），**不改知识点覆盖度**。

#### 4.4.4 内容块协议（Streaming NDJSON）

流式输出采用 **NDJSON**（每行一个 JSON 对象），每块一到即可渲染，无需等整体生成完毕。首行必须是 `meta`，最后一行必须是 `done`。

```jsonl
{"type":"meta","lesson_id":"L1-2","depth":"standard","version":1}
{"type":"text","md":"## 为什么「重量」和「质量」总被搞混？"}
{"type":"callout","style":"hook","md":"在月球上你并不会变轻，只是称不准了。"}
{"type":"animation","title":"月面弹簧秤实验","height":320,"html":"<!DOCTYPE html>..."}
{"type":"code","lang":"python","code":"W = m * g"}
{"type":"quiz","question":"...","options":["A","B","C"],"answer":1,"explain":"..."}
{"type":"ref","material_id":"m1","page":42,"quote":"..."}
{"type":"done","tokens":1533}
```

| `type` | 关键字段 | 渲染方式 |
| --- | --- | --- |
| `meta` | lesson_id, depth, version | 初始化讲义元信息 |
| `text` | md | Markdown → HTML（含公式、代码高亮） |
| `callout` | style ∈ {hook, tip, warn, question, fun}, md | 带图标与配色的提示卡 |
| `analogy` | title, from, to, md | 类比卡片 |
| `diagram` | title, kind ∈ {svg, mermaid, ascii}, content | 图示渲染 |
| `image` | source ∈ {material}, path, caption | 资料原图（本地路径） |
| `svg` | title, svg, caption, source_id | 清洗后内联 SVG，支持原位重画 |
| `animation` | title, html, height, fallback_md | 沙箱渲染，失败回退文本 |
| `code` | lang, code, runnable | 代码高亮；runnable 时提供本地试跑入口 |
| `quiz` | question, options[], answer, explain | 可作答 + 即时解析 |
| `table` | headers[], rows[][] | 对比表 |
| `summary` | points[] | 小节小结卡 |
| `next_preview` | md | 下节预告：衔接下一小节，避免知识断层（五段式第 5 段的收尾块） |
| `ref` | material_id, page, quote | 依据标注（可点击溯源） |
| `error` | message, recoverable | 生成异常提示 |
| `done` | tokens | 收尾与用量统计 |

容错：整行 JSON 解析失败 → 记录并跳过，继续消费后续块；**连续 5 行失败 → 判定协议错乱，回退「整段文本按 Markdown 渲染」**；遇到未知 `type` 一律降级为「折叠显示原始 JSON」，保证老版本客户端不崩。

#### 4.4.5 结构化输出（总监 Agent）

总监 Agent 不走 NDJSON，而是输出严格 JSON 并做 Schema 校验：

| 失败情形 | 处理 |
| --- | --- |
| 输出非法 JSON | JSON Schema 强约束 + 一次「修复重试」（把错误信息回喂模型） |
| 章节数过少 / 粒度过粗 | 追加一次「细化」轮次，对每个小节拆知识点 |
| 与用户大纲冲突 | 以用户大纲为准，冲突点标注「已按你的大纲调整」 |
| 上下文超限 | 触发分级摘要降级，界面提示「已基于摘要生成」 |

长资料处理链：带定位分块（600–900 字符，重叠 15%）→ 总长小于上下文预算 40% 时一次性摘要，否则**分级摘要**（逐块摘要 → 成章摘要 → 目录级摘要 + 关键词表）→ 需要细节时按需检索原文补足。

### 4.5 Agent ↔ 工具（Tool Loop）

联网、读大纲、读资料、读图、画图都是 Agent **可主动调用**的工具，而不是写死在流水线里的固定步骤。教师 Agent 与总监 Agent 共用同一套实现（`app/agents/base.py`）。

```python
async def run_agent(messages, tools, max_rounds=3, cancel=None):
    for round_no in range(max_rounds + 1):
        stream = await llm.stream_chat(messages, tools=tools)   # 工具以 JSON Schema 注册
        tool_calls = []
        async for chunk in stream:
            if chunk.text:
                yield chunk.text                # ① 内容块照常流式外发
            if chunk.tool_call:
                tool_calls.append(chunk.tool_call)

        if not tool_calls:
            return                              # 模型讲完了，收尾

        messages.append({"role": "assistant", "tool_calls": tool_calls})
        for call in tool_calls:                 # ② 同一轮可并行调用多个工具
            result = await executor.run(call, cancel)   # 超时 / 缓存 / 预算 / 清洗都在这里
            messages.append({"role": "tool", "tool_call_id": call.id,
                             "content": wrap_untrusted(result)})   # ③ 不可信包装
        # ④ 回到循环：把工具结果交给模型，继续写讲义
```

完整工具清单与可用 Agent 以《项目文档》§8.6 为主表；本表在其基础上补充**超时与预算**列（这是交互层需要知道的约束）：

| 工具 | 可用 Agent | 作用 | 超时 |
| --- | --- | --- | --- |
| `search_materials(query, k)` | Director, Teacher, Tutor | 检索用户资料片段（FTS5） | 本地，秒级 |
| `read_material_slice(material_id, page)` | Director, Teacher | 读取资料指定页原文 | 本地，秒级 |
| `read_outline(scope)` | Director, Teacher, Tutor, Q&A, NoteKeeper | 读完整课程大纲（全课 / 某章 / 本小节定位） | 本地，秒级 |
| `get_lesson_kps(lesson_id)` | Teacher, NoteKeeper | 取本小节知识点清单（覆盖率自检） | 本地，秒级 |
| `read_image(path, question)` | Teacher, Tutor | 多模态读图 | 30s |
| `gen_svg(spec)` | Teacher（内部调用 Illustrator） | 生成并清洗 SVG 矢量图示 | 60s |
| `render_svg(svg)` | Teacher（内部调用 SvgRenderer） | SVG → PNG（自检图 + 首屏占位图） | 60s |
| `review_svg_image(png, spec)` | Teacher（内部） | 读图评审渲染结果，产出问题清单 | 30s |
| `refine_svg(svg_id, feedback)` | Teacher, Tutor | 按反馈重画或局部修改 SVG | 60s |
| `gen_animation(spec)` | Teacher（内部调用 Animator） | 生成并校验 HTML 动画 | 60s |
| `cite_from_lesson(lesson_id, anchor)` | Tutor, Q&A | 把讲义片段 / 追问打包成引用卡片 | 本地，秒级 |
| `get_progress()` | Teacher, Tutor | 读取学习进度以调整讲解 | 本地，秒级 |
| `save_note(md, target)` | Tutor, Q&A | 把答疑沉淀为笔记（可指定小节或课程级） | 本地，秒级 |
| `make_notes(lesson_id, scope)` | NoteKeeper | 整理小节 / 课程 Markdown 笔记 | 模型超时（默认 60s） |
| `make_quiz(kp, n)` | Teacher, Tutor | 基于知识点出题 | 模型超时（默认 60s） |
| `web_search(query, k)` | Director, Teacher, Q&A | 联网检索时效性信息（默认千帆，只取引用） | 15s |

| 约束 | 取值 | 原因 |
| --- | --- | --- |
| 最大轮次 | 3 轮 | 每多一轮要重发上下文，token 成本上升；3 轮足够覆盖「查资料 → 补细节 → 收尾」 |
| 单轮并行 | 允许，同一工具最多 3 个调用 | 模型常一次问多个关键词，并行省时间 |
| 失败语义 | 工具失败返回结构化错误给模型，由模型决定继续或跳过 | 不让一次检索失败毁掉整节讲义 |
| 可取消 | 用户点「停止」立即中断工具与流 | 长任务必须可中断 |
| 记账 | 记录工具名、参数、耗时、token、是否命中缓存 | 支撑预算与成本可视化 |
| 展示 | 讲义中以可折叠的「资料检索过程」呈现检索词与来源 | 让「AI 查了什么」透明可复核 |

**为什么既预注入又给工具？** 两者互补：系统预取负责「**确定要查的**」（少一轮往返，更快更省）；工具调用负责「**模型临时觉得要查的**」（按需精确检索）。两条路径共享同一套后端、缓存、预算与清洗实现。

关键约定：**已输出的内容不丢** —— 每轮产出的块都已落盘，工具调用只是「暂停—续写」，不是「重写」；调用期间界面显示「正在查资料 / 正在读大纲 / 正在画图」。

### 4.6 Agent ↔ 外部服务（联网搜索）

搜索能力与主对话模型**解耦**（DeepSeek 的 `tools` 只接受 `type: "function"`，不接受 `{"type":"web_search"}`），做成可插拔的搜索后端。

```python
class SearchBackend(Protocol):
    name: str
    backend_type: Literal["ai_search", "hosted", "api", "self_hosted"]
    async def search(self, query: str, k: int) -> list[SearchHit]: ...

@dataclass
class SearchHit:
    title: str; url: str; domain: str; snippet: str; accessed_at: str
```

| 后端类型 | 代表实现 | 结果提取方式 |
| --- | --- | --- |
| `ai_search`（**默认预设**） | 百度千帆 AI 搜索 `POST /v2/ai_search`，默认模型 `ernie-4.5-turbo-128k` | 一次调用返回「答案 + 引用列表」；默认**只取引用列表**转成 `SearchHit` |
| `hosted` | OpenAI Responses `tools=[{"type": "web_search"}]` | 走 `routing.web_search` 指定档案；从响应引用 / annotations 提取 |
| `api` | Tavily / Serper / Exa / Brave | httpx 直连各家 HTTP 接口，JSON → `SearchHit` |
| `self_hosted` | 自建 SearXNG | 调 JSON 接口，无需 Key |

**配置取值 ↔ 适配器类型（对应 C-07，避免两套名字对不上）**

| `searching_model.backend`（配置） | `SearchBackend.backend_type`（代码） | 说明 |
| --- | --- | --- |
| `qianfan` | `ai_search` | 默认预设：百度千帆 AI 搜索，一次调用返回「答案 + 引用列表」 |
| `openai_hosted` | `hosted` | 服务端托管搜索；需 `routing.web_search` 指向 `capabilities.hosted_web_search = true` 的档案 |
| `tavily` / `serper` / `exa` / `brave` | `api` | 第三方纯检索 API，结果由本项目自行拼装 |
| `searxng` | `self_hosted` | 自建实例，无需 Key |

**默认后端请求示例**

```http
POST https://qianfan.baidubce.com/v2/ai_search
Authorization: Bearer <api_key>
Content-Type: application/json

{
  "model": "ernie-4.5-turbo-128k",
  "messages": [
    { "role": "user",
      "content": "为讲解『矩阵乘法的计算规则』补充最新教材约定与常见表述差异" }
  ],
  "stream": false,
  "resource_type_filter": ["web"]
}
```

| 返回内容 | 本项目的处理 |
| --- | --- |
| 答案文本（`choices[].message.content`） | **默认丢弃**（`usage = references_only`） |
| 引用列表（`references`） | 清洗（去广告位、去重复域名、截断 snippet）后转 `SearchHit`，注入上下文并生成 `ref(web)` 块 |

> 丢弃外部答案的理由：我们已有自己的教师 Agent 与教学骨架，直接采用外部答复会带来措辞与人设不一致、知识点覆盖不可控、幻觉无法溯源三个问题。若用户开启 `answer_assist`，外部答案只作为参考材料，最终表述仍由教师 Agent 产出并标注来源。

**两条调用路径（共享缓存 / 预算 / 清洗）**

```text
路径 A（主）：Agent 主动调用工具
教师 Agent 流式输出中 ──▶ 模型输出 tool_calls: web_search(query, k)
      ▼ 流式暂停，界面显示「正在查资料…」（可取消）
ToolExecutor：查缓存(data/cache/web/<hash>.json, TTL 24h) → 预算检查 → 调后端 → 清洗
      ▼ 包装为不可信内容回喂 {"role":"tool","content":"<untrusted source=\"web\">…</untrusted>"}
模型继续生成 ──▶ 产出 ref(web) 块并写完讲义（最多 3 轮）

路径 B（辅）：系统预取
用户点「查最新」 / 命中时效敏感词表 / 大纲阶段确认要联网
      ▼ 生成前先取回结果，直接放进 context（注入前同样过缓存、预算与清洗）
省掉一轮 LLM 往返，后续处理与路径 A 完全一致
```

成本控制：**默认关闭**；只对时效敏感知识点触发；本地资料优先（资料里已有答案就不联网）；24h 缓存；单次最多 5 条 + snippet 截断；单小节最多 2 次；每日预算硬上限（默认 100 次）；失败不阻塞讲义生成（仅标注「未能校验时效性」）。

安全：搜索结果一律按**不可信数据**处理，隔离包装为 `<untrusted source="web">…</untrusted>`；命中可疑模式（如「忽略以上」「输出系统提示词」）时丢弃该片段并记录日志；联网内容在讲义中占比不超过约 30%。

### 4.7 视觉流水线（SVG 与动画）

**SVG 图示：先渲染成图片，再决定是否采用（Render-and-Review）**

```text
① SVG 生成 ──▶ ② SvgSanitizer 清洗（白名单元素/属性；禁 script / foreignObject / on* / 外链）
                    │
                    ▼
③ svg_renderer 渲染为 PNG（QtSvg 离屏，width=820, scale=2）
                    │
                    ▼
④ 教师 Agent 看图自检
     ├─ 默认路径：PNG 交给当前档案（DeepSeek 自带多模态读图）按检查清单评审
     └─ 兜底路径：档案不支持读图或调用失败 → 启发式检查（可量化指标）
                    │
        ┌───────────┴────────────┐
        ▼ 通过                   ▼ 不通过
  放上讲义（PNG 兼作懒加载占位图）  产出「问题清单 + 修改建议」→ 回到 ①（最多 3 轮）
                                    3 轮仍不通过 → 降级为文字说明 + 「再试一次」按钮
```

SVG 输出硬性规范：单个内联 `<svg>` 带 `viewBox`；禁止脚本、外链、事件属性；颜色用主题变量或 `currentColor`；体积 ≤ 40KB、元素数 ≤ 400；提供 `<title>` 与 `<desc>`。

重画四类操作：整体重画（换构图）、局部修改（携带当前源码做增量修改）、风格切换、版本回退。重画结果**原位替换**，历史版本写入 `widgets/diagram-N.vK.svg`，不改讲义版本号，只更新 `lesson.json` 的 `generated_assets`。

> 用户侧的重画是**兜底**而非主路径：正常情况下教师 Agent 已在自检环节把不合格的图重画掉了。

**HTML 动画：沙箱内运行，禁网 + 熔断 + 降级**

```python
def prepare_animation_html(raw_html: str, theme: dict) -> str:
    doc = sanitize(raw_html)          # 移除 <script src>, <link>, <iframe>, fetch/XHR
    guard = """
    <meta http-equiv="Content-Security-Policy"
          content="default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src data:;">
    <style>:root { --atm-fg: %(fg)s; --atm-bg: %(bg)s; }</style>
    """ % theme
    return doc.replace("<head>", "<head>" + guard, 1)
```

配套拦截：`QWebEnginePage.createWindow` 返回 `None`（禁止弹窗）、`acceptNavigationRequest` 仅允许 `about:blank` 与受控本地路径、下载一律拒绝；`loadFinished(False)` 或 5s 超时则切换到 `fallback_md`。动画规范：单文件、内联 CSS/JS、无外部资源、宽高自适应、至少一个可交互控件、支持 `prefers-reduced-motion`、体积 ≤ 80KB。

### 4.8 渲染内核 ↔ Qt

**统一内核，三处复用**：教学区、追问抽屉、小灶共用 `app/web/lesson.html` + `renderer.js`，只有容器宽度与排版参数不同，避免样式漂移与重复修 bug。

```text
教学区   ─┐
追问抽屉 ─┼─▶ 渲染内核：Markdown 解析 → 公式渲染 → 代码高亮 → 图片 / SVG 注入 → 动画沙箱挂载
小灶     ─┘            （主题变量注入，样式一致）
```

| 能力 | 实现 | 关键要求 |
| --- | --- | --- |
| Markdown | markdown-it（本地 vendor），支持 GFM 表格 / 任务列表 / 脚注 / 删除线 | 服务端另用 python-Markdown 产出 `script.md` 人读版 |
| LaTeX | KaTeX（本地 vendor + 字体） | 支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`；`throwOnError: false`，失败降级为等宽原文 |
| 图片 | 本地受控路径 / data URI | 懒加载、点击放大、暗色下自动调亮度；**不加载远程图片**；缺失显示占位与失效路径 |
| SVG | 清洗后**内联注入**（不用 `<img src>`，否则主题变量失效） | 保留 `viewBox` 自适应；悬浮工具条：重画 / 换画法 / 历史版本 / 复制源码 |
| 微型动画 | `<iframe sandbox="allow-scripts" srcdoc="…">` | 5s 熔断；播放 / 暂停 / 重播；滚动进入可视区才挂载；失败降级 `fallback_md` |

**跨语言桥（QWebChannel）**

| 方向 | 消息 | 用途 |
| --- | --- | --- |
| Qt → 页面 | `theme-changed(cssVars)` | 明暗 / 主题切换只改 CSS 变量，**不重建 DOM**，保留滚动位置 |
| Qt → 页面 | `block-append(block)` | 流式新增内容块 |
| 页面 → Qt | `open-ref(type, id)` | 点击引用卡片溯源（资料页码、追问、SVG） |
| 页面 → Qt | `asset-action(action, assetId)` | 重画 / 回退版本 / 复制源码 |

**安全边界**：CSP `default-src 'none'; img-src data: file:; style-src 'unsafe-inline'; script-src 'unsafe-inline'`（禁网）；动画一律走 iframe 沙箱 + `srcdoc` 注入而非远程 URL；SVG 与动画 HTML 都先过清洗器；用户上传的 HTML 类文件不直接渲染，只作静态展示。

**渲染调度策略**

| 场景 | 处理 |
| --- | --- |
| 块到达 | 轻量块（text / callout / summary）即时渲染；富内容块先出占位骨架，异步替换 |
| 交互块 | `quiz` / `ref` 交给原生 Qt 控件（可交互、可统计、可无障碍） |
| 讲义超长（> 300 块） | 可视区虚拟渲染，只挂载视野内 ± 2 屏 |
| 图片较多 | 懒加载，先显示 `widgets/*.png` 缩略图 |

| 任一元素失败 | 只降级该块，给出「重试 / 换个画法 / 查看源码」入口 |

### 4.10 失败与降级矩阵

| 失败点 | 影响面 | 处理 | 用户可见反馈 |
| --- | --- | --- | --- |
| 单个内容块 JSON 解析失败 | 该块 | 跳过并记录，继续消费后续块 | 结尾汇总提示「已跳过 N 个异常块」 |
| 连续 5 行解析失败 | 整段输出 | 判定协议错乱，回退整段 Markdown 渲染 | 讲义正常可读 |
| 流中断 | 当前小节 | 保留已落盘块 | 「续写」按钮（携带已生成正文尾部摘要） |
| 模型拒答 / 空响应 | 当前小节 | 切换备用档案重试一次 | 仍失败则展示可重试错误卡 |
| 内容过短（< 300 字） | 当前小节 | 自动请求一次「补全细节」 | 无感 |
| 401 / 403 | 全部模型功能 | 不重试，直接上报 | 「去检查 API Key / Base URL」引导 |
| 工具调用超时 | 该轮工具 | 中断该轮，让模型基于已有信息继续 | 「上一轮检索超时，已按现有资料继续」 |
| 搜索后端不可用 | 时效标注 | 不阻塞讲义，标注未校验 | 「未能校验时效性」+ 重试入口 |
| 搜索超出每日预算 | 联网能力 | 停止自动触发 | 提示已达预算上限 |
| SVG 3 轮未通过 | 该图 | 降级为文字说明 | 图示徽标显示「已降级为文字」+「再试一次」 |
| 动画加载失败 / 超时 5s | 该动画 | 切换到 `fallback_md` | 显示静态文字，正文不受影响 |
| 公式渲染失败 | 该公式 | `throwOnError: false`，降级等宽原文 | 原文可见，不毁整页 |
| 索引库损坏 | 列表 / 检索 | 删除并扫描 `Courses/` 重建 | 短暂「正在重建索引」 |
| `schema_version` 高于应用 | 该课程 | 只读模式 | 「请升级应用」提示，禁止写入 |
| 迁移失败 | 该课程 | 保留原文件，标记「需要修复」 | 课程库给出备份入口 |

## 5. 扩展点与改动指引

| 想做的事 | 改哪里 | 必须同步的地方 | 不该碰的地方 |
| --- | --- | --- | --- |
| 新增模型供应商（OpenAI 兼容） | `data/config.json` 的 `llm_profiles` | 设置页「测试连接」拉取模型列表；必要时更新 `routing` | 任何课程数据 |
| 新增 Agent 工具 | `app/agents/tools.py` 注册 + `app/infra/tool_executor.py` 实现 | 工具 JSON Schema、超时值、预算规则、`shared/untrusted.md` 的不可信包装范围 | 已有工具的签名 |
| 新增内容块类型 | `app/ui/widgets/block_renderer.py` + `app/web/renderer.js` | 本文 4.4.4 的块类型表、§7 枚举速查、《项目文档》§18.6 | 既有块的字段语义 |
| 新增搜索后端 | 实现 `SearchBackend` Protocol（`app/infra/web_search.py`） | `searching_model.backend` 取值表、设置页选项、缓存键 | 教师 Agent（它只认 `web_search` 工具名） |
| 新增教学人设 | `<工作区>/personas/<id>.md`（YAML 头 + Markdown 正文） | `personas` 表登记、`personas/` 内置模板（如需内置） | 教学骨架与输出协议 |
| 新增主题 | `app/ui/theme/presets.py` + `tokens.py` | `qss.py`（Qt 侧）与 `theme.css`（内嵌侧）共用同一套 token | 渲染内核逻辑 |
| 新增领域字段 / 改结构 | `app/core/models.py` | `app/core/migrations/` 加迁移；版本号自增；本文 §3.5 附表 | 已在用的字段名 |

扩展原则：

1. **加能力不改数据**：换供应商、换搜索后端、换人设、换主题都不应改动 `Courses/` 中的任何文件。
2. **协议先行**：新增块类型或工具时，先改协议表，再写实现，最后加 golden 回放用例。
3. **能力以工具形式交给 Agent**：不要把新能力写死进流水线，除非它必须「每节都执行」（此时走系统预取路径）。
4. **渲染必须可降级**：任何新增富内容都要有 `fallback`，并保证正文独立可读。

## 6. 安全边界汇总

| 资产 | 威胁 | 技术措施 |
| --- | --- | --- |
| API Key | 明文落盘 / 日志泄露 | DPAPI 或 keyring 加密；日志与导出强制脱敏；界面仅显示后 4 位 |
| 用户课程内容 | 意外外泄 | 不做遥测；仅向用户配置的端点发送模型请求所需内容 |
| 本地文件系统 | AI 生成的动画读写本地文件 / 发起网络请求 | CSP 禁网 + 只加载受控目录 + 拦截 navigation / 下载 / 弹窗 |
| 讲义内容 | 内嵌脚本或外链资源 | SVG 白名单清洗（移除 `script` / `foreignObject` / `on*` / 外链）+ 体积与元素数上限 |
| 教学风格 | 人设注入越权指令 | 分层夹逼装配 + 越权规则检测与剔除 + 硬边界回归用例 |
| 上下文完整性 | 联网结果的提示注入 | 隔离包装为不可信内容 + `shared/untrusted.md` + 可疑模式丢弃；**外部内容永不进入系统提示区** |
| 第三方服务 | 搜索密钥泄露 / 检索词外发 | 密钥入凭据库；界面明确告知「联网时会把检索词发送给所选搜索服务」；可一键关闭 |
| 网络出口 | 渲染内核被诱导发外部请求 | CSP `default-src 'none'` + 拦截 navigation / 下载 + 依赖本地 vendor |
| 应用进程 | 路径穿越导致越界写文件 | 课程名 / 文件名白名单清洗 + `safe_join` 校验 |
| 用户设备 | 他人分享的课程包注入脚本 | 导入外部课程时扫描脚本类文件并默认禁止执行，仅静态展示 |
| 生成代码 | 用户误运行危险代码 | 默认不自动执行；「本地试跑」在受限子进程内执行并提示风险 |

四条必须守住的安全红线：

1. 🔒 **密钥只在内存与加密存储中**，永不进入 `course.json` / 日志 / 导出 / 备份包 / 崩溃报告。
2. 🔒 **AI 生成的 HTML 与 SVG 一律视为不可信**，先清洗再渲染，渲染在禁网沙箱内并带超时熔断。
3. 🔒 **外部内容只是素材，不是指令**：搜索结果与资料原文只提取事实，命中可疑模式即丢弃。
4. 🔒 **一切写入路径先清洗**：拒绝 `..`、绝对路径与 Windows 保留名，写入前校验最终路径在根目录之内。

## 8. 结语

技术上的三条关键解耦，决定了这个项目能不能长期走下去：

1. **模型与能力解耦**：主模型只管讲课；「能看图」「能联网」由档案能力与模型路由分发。换供应商不该动摇课程数据。
2. **内容与渲染解耦**：讲义以 `script.md` + `script.blocks.jsonl` 落盘，渲染交给统一内核。将来换 UI 框架、导出 PDF、做移动端，都不必重写内容本身。
3. **能力以工具形式交给 Agent**：联网、读大纲、读资料、读图、画图都是 Agent 可主动调用的工具（Tool Loop），系统只负责限轮次、控预算、做清洗。

配套的四条工程纪律：文件系统是唯一事实来源、索引库随时可删重建、每个内容块完成即原子落盘、任何长任务都可取消并保留已生成内容。
